# 自定义元器件：调研与设计方案

状态：**实现中**（2026-08-26）。第二节四个开工前的问题**已由维护者拍板**，其中第 2 条在五步
做完之后被维护者**推翻**了——布局窗口现在是自由拖拽，见 12.9。第十节五步全部完成，第九节的待定
问题 3 在实现中得到了答案，且和原来的倾向相反——见第十二节。

诉求：在现在的电路编辑窗口里正常画电路，画完能「保存为自定义元器件」，存成一种新的元件格式；
保存时弹一个布局确认窗口，按 TTL 简化符号那种规整画法排端口，默认输入在左、输出在右，用户可以
把端口拖到上下左右任意一边并调整顺序；每个输入输出都必须命名，有一个没命名就不让保存；另外要有
一个元件管理面板，能把别人给的元件文件装进来并长期保留。

这份文档把结论和**得出结论的证据**放在一起，尤其是那些从 Logisim 源码里挖出来、重新调研要花
很久的事实。

---

## 一、现状：这件事已经有三条半路可以走

| 路径 | 定义行为 | 外观 | 跨工程复用 |
| --- | --- | --- | --- |
| 子电路 | 画电路 | 完整的矢量外观编辑器，端口锚点可拖，能贴动态元素显示内部状态 | 只能把**整个另一个工程文件**当库载入 |
| VHDL 实体 | 写 VHDL | `VhdlAppearance` 自动生成的框 | 同上 |
| JAR 库 | 写 Java 实现 `InstanceFactory` | Java 绘制代码 | 载入 jar |
| 组合分析 | 真值表 / 布尔表达式 | 无 | 产出的是一片门海，不是元件 |

第「半」条是 `Loader.loadCustomStartupLibraries`（`file/Loader.java:443`，上游文档
`docs/automatic_library_import.md`）：启动时扫 `logisim-defaults` 目录，把里面的 `.circ`
当库自动载入。它有三个毛病，加起来等于不可用：

- 目录写死在 `Startup.getProgramDirectory()`，取的是 jar 所在目录。MSI 装完就是 Program Files，
  普通用户没有写权限。
- 没有任何界面。
- 只挂给启动时打开的那一个工程（`gui/start/Startup.java:1069`）。之后「文件 → 新建」出来的
  工程一个都拿不到，因为新工程来自模板。

附带一个判据错位的小 bug：收录条件是 `!library.getLibraries().isEmpty()`，检查的是「这个文件
自己有没有载别的库」，而不是「这个文件里有没有电路」。

**结论**：缺的不是「怎么定义元件」，而是「定义完之后怎么变成一件能反复拿来用的东西」。

## 二、维护者已拍板的四个决定（2026-08-25）

1. **内部电路保留，但默认锁住。** 不是黑盒。有一个「解锁编辑」的动作。
2. ~~**布局窗口给「四边 + 该边顺序」两个自由度，方框尺寸自动算。** 不是自由拖拽，不是完整外观
   编辑器。~~ **2026-08-26 推翻**：改成完全自由的拖拽，框、端口、标题都能拖到任意位置。原来的
   自动算法留下来当每个新元件的起点。理由和代价见 12.9。
3. **布局在元件创建时定死，之后不可更改。** 要改只能发布新版本去替换。
4. **导入入口是一个元件管理面板**，不是一条菜单动作。

第 3 条是**发布即锁死**的决定，理由见 3.2。

## 三、代码事实（决定了后面每一个方案选择）

### 3.1 `SymbolLayout` 只有左右两列，没有上下

`std/symbol/SymbolLayout.java` 的模型是 `left` / `right` 两个 `SymbolRow` 列表，
`side(boolean leftSide)` 二选一，高度就是 `TOP_MARGIN + rows() * PITCH + BOTTOM_MARGIN`。
要支持四边，这个类得从「两列」扩成「四边」，不是直接拿来用。这是本功能第一块实打实的工作量。

### 3.2 端口位置是工程文件里的绝对坐标

`SymbolLayout` 里 `LABEL_CHAR_WIDTH` 上方那段注释是本设计最重要的一条既有事实：字符宽度被写成
固定常数而不是从 `FontMetrics` 量，因为方框宽度决定右侧端口坐标，而**工程文件里存的是绝对坐标**
——宽度若来自本机字体，同一个电路在字体不同的机器上连线就会落在别处。

这条约束直接推出两件事：

- 新的四边尺寸算法**同样不许碰 `FontMetrics`**，一切来自固定常数与端口数。
- 一个元件的端口位置一旦被别的电路用上，就不能再动。这正是第二节第 3 条决定的由来，也和
  Feature 12 的记录一致：改端口数会让每一个已保存文件里的连线失效。

### 3.3 `CircuitAppearance` 并不绑定 `Circuit`

`vhdl/base/VhdlAppearance.java:24` 里 `super(null)` 传的就是 `Circuit`。VHDL 实体既没有电路
也照样用这套外观机制画自己。也就是说外观系统是可以脱离电路独立构造的。

更有用的是反过来看：`AppearancePort(Location location, Instance pin)`
（`circuit/appear/AppearancePort.java:37`）把一个端口锚点绑到一个 `Pin` 实例上。**给定电路里
的一组 Pin 和我们自己算出的一组坐标，就能合成一份完整的 `CircuitAppearance`。**

### 3.4 `<project>` 下的未知元素会让官方版拒绝整个文件

`file/XmlReader.java:537` 的 `default` 分支是 `throw new IllegalArgumentException`。挂在
`<project>` 底下的未知元素不是被忽略，是让官方 Logisim-evolution **连文件都打不开**。任何新
格式设计都要绕开这条。

### 3.5 子电路已经免费给了三样最难的东西

`SubcircuitFactory` 现成提供：按放置实例分配独立状态（`getSubstate`，所以带触发器和寄存器的
元件每一份放置自动互不干扰）、传播、旋转、双击进入。自己写 `InstanceFactory` 要把这三样重做一遍。

## 四、核心决定：自定义元件就是一个带派生外观的子电路

**不新写 `InstanceFactory`。** 一个 `.pcomp` 就是一个 `LogisimFile`，里面有一个主电路、它依赖
的子电路，外加一个 `<pcomp>` 元数据元素。载入时读 `<pcomp>` 里的布局，按 3.3 合成一份
`CircuitAppearance` 设到主电路上，元件栏里出现的就是这个电路的 `SubcircuitFactory`。

这么做的收益按 3.5：状态、传播、旋转、进入全部是现成的，本功能一行都不用写。代价只有一样——
锁定要另做。

### 4.1 布局存几何，外观是派生出来的

**这一节的前半在 12.9 里改了。**原来 `<pcomp>` 存的是四边模型（每个端口在哪一边、该边第几个），
方框尺寸由 5.2 的算法算出来；现在存的是**绝对坐标**：框多大、每个端口在框上的哪一点、标题写在
哪。5.2 的算法还在，但它只负责给一个新元件铺一个起点，不再是文件里那份布局的唯一来源。

没有改的是**外观仍然是派生的**：`<pcomp>` 里存的是几何，不是 `CircuitAppearance` 的图形，载入
时按 3.3 现合成。这一条撑着第二节第 3 条的锁死——一份能画任意图形的外观一旦成了存储，用户就能
绕过布局窗口去改已发布的元件。存几何而不存图形，就没有第二份可改的副本。

### 4.2 `.pcomp` 里装什么

```
<project>                        <- 就是一个普通的 LogisimFile，官方版也读得懂
  <lib .../>                     <- 它依赖的库
  <circuit name="Adder4"/>       <- 主电路，就是这个元件本身
  <circuit name="FullAdder"/>    <- 依赖闭包里的子电路
  <pcomp id="..." version="2" main="Adder4" locked="true">
    <port name="A0" side="left"   index="0"/>
    <port name="CIN" side="bottom" index="0"/>
    ...
  </pcomp>
</project>
```

`<pcomp>` 是 `<project>` 下的未知元素——按 3.4，官方版会拒绝打开这个文件。这是**可以接受的**：
`.pcomp` 是本分支自己的元件格式，本来就不指望官方版直接打开它。真正要保证的是「**用了自定义元件
的工程**存成官方 `.circ` 时官方版能打开」，那是第八节，答案是干净的。

依赖闭包必须一起写进去，否则装到别人机器上就报缺失。两个不同的 `.pcomp` 各自带一个同名内部电路
不会撞车，`LibraryManager` 按文件路径做 key。

### 4.3 存放位置

`~/.logisim-peler/components/`。**不能用 `logisim-defaults`**——那是官方版共用的路径，会重蹈
FPGA workspace 那个覆辙（理由见 `prefs/PelerPreferences.java` 里 `defaultFpgaWorkspace()`
上方那段注释：同一个工程在两个版本里映射到同一个目录，互相删对方的产物）。

## 五、布局确认窗口

### 5.1 四边模型

**这一节在 12.9 里改了。**端口的身份现在是 `(边, x, y)`，边是从坐标反推出来的，不再有「该边
序号」。下面是草案原文。

`SymbolLayout` 从 `left` / `right` 扩成 `left` / `right` / `top` / `bottom` 四个列表。
每个端口的身份是 `(边, 该边序号)`。默认：输入按电路里 Pin 的顺序铺在左边，输出铺在右边，
inout 归右边。

窗口里画一个实时预览的方框，端口可以拖到另一边、也可以在同一边内上下换位。名字就地可编辑。

### 5.2 尺寸算法

**这一节的公式在 12.9 里改了三处**（端口居中、上下边加宽间距、元件名不再撑框），而且它现在只在
「新建一个元件」和「自动排列」这两个时候跑一次，之后用户拖到哪儿就是哪儿。下面是草案原文。

按 3.2，全部来自固定常数，一个 `FontMetrics` 都不许出现。

```
rows = max(左端口数, 右端口数)
cols = max(上端口数, 下端口数)

上带高 = 上边有端口 ? 上边最长名字字符数 * LABEL_CHAR_WIDTH + LABEL_INSET : MARGIN
下带高 = 同理
左带宽 = 左边有端口 ? 左边最长名字字符数 * LABEL_CHAR_WIDTH + LABEL_INSET : MARGIN
右带宽 = 同理

高 = 上带高 + rows * PITCH + 下带高
宽 = 左带宽 + cols * PITCH + 右带宽

高 = max(高, 元件名字符数 * CAPTION_CHAR_WIDTH + 2 * LABEL_INSET, MIN_HEIGHT)
宽 = max(宽, 元件名字符数 * CAPTION_CHAR_WIDTH + 2 * LABEL_INSET, MIN_WIDTH)

高、宽都向上取整到 10 的倍数
```

**最后那步取整不是美观问题**：Logisim 的绘图网格是 10，`PITCH` 也是 10。端口坐标必须落在 10
的倍数上，否则从元件拖出来的线永远对不齐网格。

元件名（caption）**写在框内正中**，不像 TTL 符号那样固定占顶部一条。因为四边都可能有端口，
顶部不再必然是空的。

### 5.3 上下两边的端口名怎么写

**这一节在实现时被推翻了，见 12.2。**下面是草案原文。

左右两边的名字沿水平方向写在框内（`LABEL_INSET` / `LABEL_GUTTER` 就是干这个的）。上下两边没有
水平空间，名字**旋转 90 度竖排、同样写在框内**。这也是 5.2 里上下带高按名字长度算的原因。

倾向这个方案而不是「写在框外」：写在框外的话方框的绘制包围盒和它的逻辑边界就不一致了，
`getOffsetBounds` 要额外处理，而且相邻元件靠近时名字会互相压。

### 5.4 命名校验

保存按钮的启用条件，三条全过才行：

- 每个端口都有名字，非空、去掉首尾空白后仍非空。
- 同一个元件内端口名不重复。
- 元件本身有名字，且个人元件库里没有同名同版本的。

名字的来源和去处是电路里 `Pin` 的 label——布局窗口里改名会写回 Pin 的 label。这是有副作用的，
窗口标题上要说明。

暂**不**强求端口名符合 VHDL 标识符规则（`VhdlContent.labelVHDLInvalid` 现成可用），因为现在
连符号芯片都还不支持 HDL 导出（见 ROADMAP 的 Known open items）。等哪天做 HDL 导出再补，
届时是新增校验而不是改语义。

## 六、锁定、端口签名与版本

### 6.1 锁定挡住什么

`<pcomp locked="true">` 是元件自己的属性，不是全局设置。锁住时：

- 双击实例不进入内部电路（挡 `SubcircuitFactory` 那条进入路径）。
- 工程浏览器里这个元件不展开出内部电路。
- 「编辑电路外观」对它不可用——这一条**即使解锁也照样挡**，因为按第二节第 3 条布局是定死的，
  外观是 4.1 派生出来的，让人手改它会让派生模型和实际外观脱节。

「解锁编辑」= 用主窗口直接打开那个 `.pcomp` 文件本身。它是个 `LogisimFile`，本来就打得开，
不需要新机制。

### 6.2 端口签名

定义为一个有序列表，每项是 `(名字, 方向, 位宽, 所在边, 该边序号)`。位宽取自 Pin 的
`StdAttr.WIDTH`。

**保存回同一个元件时，端口签名必须逐项相等。**不等就不许覆盖保存，只能「发布为新版本」。
这条规则同时挡住了「解锁后在内部电路里加了个 Pin」这个漏洞——加 Pin 会改签名，于是被规则捕获，
而不是悄悄改变一个已经被别人用着的元件。

### 6.3 发布新版本与替换

元件的身份是 `id`（创建时生成的稳定 UUID）加 `version`（单调递增的整数）。两个版本是两个不同的
元件类型，可以在同一个工程里共存。

管理面板里的「替换」动作把当前工程里所有 `id@v1` 的实例换成 `id@v2`：

- 签名相同 → 直接换，连线一根都不动。
- 签名不同 → **按名字**逐个比对（每个端口都有名字是硬性要求，所以名字是稳定身份），列出差异，
  例如「端口 CIN 从左边第 3 个移到了下边第 1 个」，再让用户确认。

签名不同时接在旧位置上的线**保留原样**，变成看得见的悬空线头。这和 Feature 12 处理丢失符号芯片
是同一套哲学，`file/PelerCompat.java` 里 `hasSymbolChips` 上方那段注释说得最清楚：宁可留下
显眼的断线，也不要一个能打开、却在悄悄算别的东西的电路。

## 七、元件管理面板

Project 菜单 →「自定义元件…」。

列表按元件名分组，每组下列出各个版本。每行显示：名字、版本、端口数、来源文件、当前工程是否在用。
动作：导入、删除、重命名、分组、发布新版本、把工程里的某版本替换为另一版本、打开编辑（解锁）。

删除要挡住「当前工程正在用」的版本，或者至少警告。

### 面板管不了的一件事：放置

面板负责装、卸、换版本。但**元件本身还得能从元件栏里拖出来**，否则装了也放不出来。所以元件栏里
仍然要有一个「我的元件」顶层节点。

这一条是「能用」的必要结果，不是在四个已拍板决定之外另加的需求，写在这里是为了不让它被漏掉。

顶层节点单独一个，**不和 Gates、Plexers 混在一起**：`default.templ` 的 `<lib>` 列表是脆的
（一个 `--` 就废掉整个模板，见 CLAUDE.md），而且混在一起会让「这个电路别人能不能打开」变得
不可预测。自定义元件不进 `Builtin.java`，也不动 `default.templ`。

## 八、上游兼容：这次是干净的降级

一个用了自定义元件的工程存成官方 `.circ` 时，把每个自定义元件**内联成一个普通子电路**，并按
4.1 的算法生成等价的 `CircuitAppearance` 一起写进去。

**端口坐标逐个相等，所以连线一根都不会错位。** 这是 Feature 12 当年做不到的事——74xx 符号和
DIP 封装的端口排布本来就不同，降级会让每根线接错地方，只能整片丢弃并警告。这次做得到，因为端口
位置是我们自己定义的，两边走的是同一套坐标。

于是这不构成「有损保存」意义上的内容丢失，`PelerCompat.isLossy` 不必为它返回 true。丢的只是
「它是一个元件」这层身份和版本号，电路的行为和外观完全保留。仍然值得提示一句，因为这是单向的：
官方版存回来之后它就只是个普通子电路了。

两个要处理的细节：内联电路的名字可能和工程里已有的电路撞车，需要消歧；compat 保存是一次性写出，
**绝不能污染内存里的 `LogisimFile`**——`XmlWriter` 的 compat 模式现在是「写的时候过滤」，
这里要变成「写的时候合成」，改动比过滤大。

## 九、开工前还需要定的问题

1. **扩展名叫什么。** `.pcomp`？还是别的。定了就锁死，和 `.pcirc` 一样。
2. **一个文件装一个元件，还是可以装一包。** 一包（`.pcompack`）在分发时方便，但让 4.2 的结构和
   6.2 的签名规则都要多一层。倾向先做「一个文件一个元件」。
3. **上下两边的端口名竖排在框内**（5.3 的倾向）是否认可。这是发布即锁死的决定，改了会挪端口坐标。
4. **元件栏里的组织方式**：一个「我的元件」节点下平铺，还是支持用户分组成子节点。
5. **要不要给「个人元件库目录」一个可配置的 preference。** 若加，`PelerOptionsTest
   .testEveryPelerPreferenceIsReachableFromThePreferencesWindow` 要求它必须在
   `gui/prefs/` 下某个面板上出现，否则构建直接挂。

## 十、分步计划（每步都有可验收的产物）

**第一步 —— 四边布局模型，纯逻辑无界面。** `SymbolLayout` 扩成四边，实现 5.2 的尺寸算法。
产物是单元测试：各种端口数组合下，方框尺寸和每个端口坐标都是确定值，都落在 10 的网格上，
全程不碰 `FontMetrics`。

**第二步 —— `.pcomp` 读写与派生外观。** 定格式、写读写器、按 3.3 从四边模型合成
`CircuitAppearance`。产物：手工造一个 `.pcomp`，能出现在元件栏里、拖得出来、连得上线、跑得对。

**第三步 —— 「保存为自定义元件」与布局确认窗口。** 拖拽、改名、5.4 的三条校验、依赖闭包计算。
产物：从零画一个电路，存成元件，重启后还在。

**第四步 —— 锁定、端口签名、版本与管理面板。** 6.1 到 6.3 加第七节。产物：改一个元件的布局
必须走新版本；替换动作在签名不同时如实报出差异。

**第五步 —— compat 降级、12 语种字符串、文档。** 第八节。产物：一个用了自定义元件的工程存成
`.circ`，用 `XmlReader` 读回来，端口坐标逐个相等。

## 十一、已知风险

- **第八步那个 compat 合成是本功能最大的一块未知。** `XmlWriter` 的 compat 模式从「过滤」变成
  「合成」是结构性改动，而且不能污染内存模型。如果第五步做不动，退路是照 Feature 12 那样整个丢弃
  加有损警告——功能上退了一步，但不阻塞前四步。
- **端口签名规则会挡住一部分用户直觉。**「我就改个端口名字」在这套规则下是要发新版本的。这是第二节
  第 3 条决定的直接后果，不是实现偷懒，但界面上得把理由说清楚，否则会被当成 bug 报上来。
- **五个待定问题里第 3 个（竖排端口名）一旦发布就锁死。** 它决定端口坐标，改了会让所有已保存的
  电路连线错位。宁可在第一步之前多花半天定下来。

## 十二、实现记录

### 12.1 第一步（2026-08-26）：布局模型没有做进 `SymbolLayout`

草案 3.1 和 5.1 都写的是把 `SymbolLayout` 从两列扩成四边。实现时**另建了
`com.cburch.logisim.pcomp` 包**，里面是 `PortSide` / `PortPlacement` / `PortLayout` 三个新类，
`SymbolLayout` 只放宽了三个常数的可见性。

理由是第四节那个决定的直接后果：自定义元件的绘制走 `CircuitAppearance`，根本不经过
`SymbolGate`。四边支持塞进 `SymbolLayout` 之后 `SymbolGate` 一次都不会用到它，等于在一个正给
63 片芯片供图的类里放一段死代码，而且改它就得冒动到那 63 片的风险。

借过来的是三个**纯文本度量**：`LABEL_INSET`、`LABEL_CHAR_WIDTH`、`CAPTION_CHAR_WIDTH`，从包
私有放宽到 public。这三个的含义在两边完全一样（「这个分支的符号里一个字符有多宽」），共享是对的；
`TOP_MARGIN` 之类的边距**没有**借，因为在四边模型里它们不再是同一件事——标题不再固定占顶部一条。

`PortPlacement` 存的是**名字**而不是端口下标，理由和 `SymbolRow` 存下标而不是名字是同一条：
一件事只说一遍。电路里 Pin 的顺序不保证跨编辑稳定，用下标绑定会在有人挪了一个 Pin 之后悄悄指向
另一个。方向和位宽同样不存——`Pin` 已经说了。

### 12.2 上下两边的端口名改成横排（回答了第九节的问题 3）

草案 5.3 打算把上下两边的名字旋转 90 度竖排。**做不到**：`com.cburch.draw.shapes.Text` 没有
角度属性，`DrawAttr` 里也没有，`EditableLabel` 里也没有。外观模型画不出转过的文字。

改成：上下两边的名字和其余两边一样横排，**把间距撑到装得下最长的那个名字**，那两条边的带高
因此固定为一行。副作用是 5.2 的尺寸算法不再四边同构——左右两边的带宽随名字长度变，上下两边则是
间距随名字长度变。

顺带定死了一条：上下两边的**间距取 20 的倍数**，端口坐落在自己那一格的正中。这样半个间距仍然
落在网格上，而且第一个和最后一个名字自然待在框内，不需要为两端加特例。

实测一个四边都有端口的例子（三入两出，外加 CARRY_IN 在上、CARRY_OUT 在下）：方框 120 x 70，
左带 20、右带 40、上下带各 20、上下间距 60，七个端口坐标全部落在 10 的网格上。

### 12.3 第一步的测试

`PortLayoutTest`，293 个用例（大部分来自 71 种端口数量组合的参数化）。守的是三件事后期极难查的
问题：端口偏离网格半格（画得出来但接不上线）、方框尺寸来自本机字体（这台机器上一切正常，别人打开
时每根线都错位）、标题压在端口名上（看起来像绘制 bug，其实是尺寸算错）。

最后一条用的办法值得记一笔：**测试直接读 `PortLayout.class` 的字节码**，只要常量池里出现
`FontMetrics`、`java/awt/Font`、`stringWidth` 之类就判失败。这是 3.2 那条约束唯一没法靠人眼
维持的守卫——`FontMetrics` 是哪天顺手加进来的都很难在评审里看出来。

### 12.4 第二步（2026-08-26）：`.pcomp` 的读写与派生外观

格式落地时和草案 4.2 有三处不一样。

`<port>` 的序号属性叫 `slot` 不叫 `index`。`index` 在这套代码里已经被 `Library.indexOf`
那种「第几个工具」占着了，而这里说的是「该边第几格」，两件事混一个词迟早会读错。

`<pcomp>` 多了一个 `name`。**`name` 和 `main` 是故意分开的两样东西**：`name` 是用户给元件起的
名字（`MyAnd`），`main` 是这个元件的主电路名（`MyAnd_v1`）。为什么必须分开见 12.6。手写一个
`.pcomp` 时 `name` 可以省，省了就取 `main`。

派生外观要**同时**把 `CircuitAttributes.APPEARANCE_ATTR` 设成 `APPEAR_CUSTOM`。只调
`setObjectsForce` 是不够的：`CircuitAppearance.isDefaultAppearance()` 读的是那个属性，它为真时
刚设进去的图形会被重新生成的默认方框顶掉——元件照样载入、照样能放，只是画出来是个普通子电路，
端口全在别处。这是本步最容易漏、又最难从现象倒推回原因的一条。

目录扫描有一条**重入保护**，不是防御性代码：读一个元件文件要 `Loader`，每个 `Loader` 都建一个
`Builtin`，而 `Builtin` 现在持有 `PcompCatalogLibrary`，于是一个元件文件在被读的过程中会重新
进入正在读它的那次扫描。扫描进行中一律回答空列表就断掉了这条环，代价是「用别的元件搭出来的元件」
看不见那些元件——目前没有任何东西会写出这种文件。

扫描中**一个读不出来的文件是跳过，不是抛出**。这个目录里装的是用户自己放进去的东西，而且是在
程序启动过程中读的，一个坏文件不能有本事让程序打不开。

**这一步偏离了第七节最后一句「自定义元件不进 `Builtin.java`，也不动 `default.templ`」。**
两个都动了，但动的不是元件：`Builtin` 里注册的是 `PcompCatalogLibrary` 这个**空壳类目**，
`default.templ` 里加的也只是一行 `<lib desc="#My Components" .../>`。不这么做新建工程里根本
不会有「我的元件」节点——注册进 `Builtin` 是必要不充分条件，新工程只加载 `default.templ` 点名的
那些库（见 CLAUDE.md）。草案那句话真正想守的是「具体的元件不硬编码进程序」，那一条没有破。

### 12.5 第三步（2026-08-26）：保存为自定义元件与布局确认窗口

`PcompWriter` 在**克隆**上做依赖闭包裁剪，原工程一个电路都不掉。工程里通常还装着别的活，一个
把它们全带上的元件会随着它碰巧诞生在哪个工程而长大。

布局窗口 `PcompSaveDialog`：左边是预览框，端口拖到哪条边就落到哪条边，双击改名；右边是端口表。
5.4 的三条校验合成一句话显示在底部，不合格时保存按钮直接灰掉，不弹框。

### 12.6 第四步（2026-08-26）：版本共存逼出来的一条硬约束

**两个版本必须叫两个不同的电路名。** 工程文件把一个放置的元件记成
`<comp lib="N" name="电路名"/>`，而 `PcompCatalogLibrary.toolsOf` 按工具名（= 电路名 =
`SubcircuitFactory.getName()` = `Circuit.getName()`）去重。如果两个版本都叫 `MyAnd`，要么
用了 v1 的老工程重新打开时悄悄绑到 v2 上，要么替换动作根本没有两个东西可换、工程存都存不下来。
所以 `mainCircuit = name + "_v" + version`。

**是下划线不是空格。**`CircuitAttributes` 的 NAME_ATTR 监听器会跑
`SyntaxChecker.isVariableNameAcceptable(newName, true)`，它拒绝空格，而且**拒绝时会弹一个模态
对话框**。`MyAnd_v1` 过得去，`MyAnd v1` 过不去——而这次调用发生在写文件的过程中。

**画在框里的标题仍然是裸名字**（`MyAnd`），不带版本号。方框宽度是按标题长度算的，标题里塞版本号
会让 v10 比 v9 宽一格，同一个元件换个版本方框就变形。

改名做在**写出去的 XML 上**，不走 `Circuit.setName`——理由同上，监听器会在扫描中途弹框。DOM 里
名字出现三处：`<main name>`、`<circuit name>`，以及 `<circuit>` 内部的 `<a name="circuit"
val>`。读的时候后者盖前者，所以少改一处就得到一个「电路名和元数据对不上」的文件。

锁定有五道门（元件栏双击、右键菜单的编辑布局/编辑外观、放置实例上的双击、`configureMenu` 里那条
「查看」、主菜单的编辑外观），全部收敛到 `pcomp/PcompLock.java` 一个类里，免得五处策略各自漂移。

**元件栏里双击一个锁定的元件是装填连续放置**，和双击一个内建门一模一样，不弹框。弹框只留给
`SubcircuitPoker` 上那次双击——那个手势的唯一含义就是「让我进去」，它被挡住时用户需要知道为什么。

`PortSignature.differences` 返回的是**结构化的差异记录**，不是拼好的句子，措辞由 GUI 层的
`PcompText` 负责。这样 `com.cburch.logisim.pcomp` 整个包不带语言，比较逻辑也就能脱离 locale
去测。

**这一步没有做第七节列的「重命名」和「分组」两个动作。** 重命名一个已发布的元件会打断所有引用
它的工程——和第二节第 3 条「布局发布即锁死」是同一条理由，唯一正确的改名方式也是发布新版本。
分组在一个平铺的目录里没有对应物：目录里就是一堆文件，分组要么只是界面上的假象，要么就得再发明
一层存储。理由写进了 `PcompManagerDialog` 的类注释。

`PcompCatalog` 是**进程级**注册表，于是加了一个 `useDirectory` 的测试接缝。没有它，目录测试读的
是跑测试的人自己装了什么，过不过取决于机器——对一个全进程共享的注册表来说，这正是那种只在别人机器
上出现的问题。

### 12.7 第五步（2026-08-26）：compat 降级比预想的干净

第十一节把这一步列为「本功能最大的一块未知」。实际做下来是三个钩子加一个规划函数：
`file/PcompLowering.java` 先算出「哪些电路要内联、各叫什么名字」，`XmlWriter` 里
`fromLoweredComponent`（放置处写成不带 `lib` 的普通子电路引用）、`fromLoweredCircuit`（把电路
按新名字写进文件）、以及 `fromLibrary` 里把 `PcompCatalogLibrary` 整个略过。

**内存模型一行都没动**，合成只发生在正在写出的 DOM 上。第八节担心的「污染」没有发生，因为
`fromCircuit` 本来就是从 `Circuit` 现读现写的，给它一个别的名字不需要先把那个名字写回电路里。

一个没预料到的坑：**内联电路里的元件解析不到库**。`Library.contains` 比的是工厂对象的身份，而
通过 `FactoryDescription` 声明的内建元件（`Register`、`Counter` 这一批）是**每个库实例各造一个**
的，不是单例；元件目录用的是它自己的 `Loader`，那个 `Loader` 建了另一套内建库。于是内联进来的
电路里那些元件，和工程里同名的那些，除了 `Library.contains` 问的那一点之外处处相等。
`findLibraryOffering` 改成**按名字**找库。这不是将就:`<comp lib name>` 本来就是靠这两个字段
解析的，按名字匹配就是那个问题本身。

重名消歧按 `_1`、`_2` 往后加，大小写不敏感——`LogisimFile` 判断一个电路名是否已存在时就是这么比的。

放置处**不需要额外剥掉 `circuit` 属性**：`CircuitAttributes.isToSave` 对所有静态属性一律返回
false，NAME_ATTR 是其中之一，所以一个子电路从来就没写过它。查清楚这一点之后删掉了一段本来写好的
剥离代码。

按第八节的结论，这不进 `PelerCompat.isLossy`，也不加保存警告：电路、外观、连线全部原样保留，
丢的只是「它是目录里的一个元件」这层身份。理由记在 `isLossy` 上方。

### 12.8 第九节那五个问题的现状

1. **扩展名** —— `.pcomp`，已锁死。
2. **一个文件一个元件还是一包** —— 仍是一个文件一个元件，没有做包。仍然开着。
3. **上下两边端口名竖排** —— 做不到，改成横排，见 12.2。已锁死。
4. **元件栏组织方式** —— 「我的元件」下平铺，不做分组，理由见 12.6。
5. **个人元件库目录的 preference** —— 没有加。`PcompCatalog.directory` 现在是个普通字段，
   没有对应的 preference，所以 `PelerOptionsTest` 不会被触发。仍然开着。

### 12.9 自由布局（2026-08-26）：第二节第 2 条被推翻

五步做完之后，维护者拿一个 `halfadder` 试了一遍，结论是「太丑了」，要求布局窗口能像工作区域一样
手动拖拽调整距离和大小。选的档位是**完全自由，像个小外观编辑器**：框、端口、标题全部能拖到任意
位置，位置一律存绝对坐标。第二节第 3 条（发布即锁死）不变。

#### 那张图丑在哪

照片上是一个 170x60 的扁盒子，A / B 挤在左上角，Sum / Cout 挤在右上角，下面一大片空的。三个原因
叠在一起，全都能从旧算式里算出来：

- **端口贴着上带排**，坐标从 `顶带高` 开始一个个往下加，富余全落在下面。
- **`PITCH` 和 `LINE_HEIGHT` 都是 10**，相邻两个端口名的两行字正好首尾相接。
- **元件名按 `captionWidth + 2 * max(左带宽, 右带宽)` 撑框**，`halfadder` 九个字符 87 宽，
  两边各 40，撑到 167 再取整成 170。

这三条和「自由不自由」无关，是自动布局本身算错了，所以不管维护者怎么选都要修。修法：端口在
**两条带之间**居中（不是在框的两条边之间——带里写的是另外两边的端口名，穿过去就压字），`PITCH`
改成 `2 * GRID`，元件名改成只保证 `宽 >= 左带 + 名字宽 + 右带`、且**居中在内区**而不是居中在
整个框。`halfadder` 现在出来是 150x60，端口在 20 / 40，正是上面那张图该有的样子。

#### 模型层：`(边, 序号)` 换成 `(边, x, y)`

`PortPlacement` 从 `(name, side, slot)` 变成 `(name, side, x, y)`。`PortLayout` 从「一个算式」
变成「一份记录」：构造函数收下框宽高、标题坐标和一串端口坐标，只做两件事——吸到 10 的网格上、
拒绝重叠。原来的算式搬进 `PortLayout.automatic`，它现在只是**起点的提供者**。

`PortSide` 留着，但它的角色变了：它不再是位置的一半，而是从坐标反推出来的一个**朝向**——决定
桩子往哪边伸、名字写在框内的哪一侧。新的 `PortSide.nearest(x, y, w, h)` 按「离哪条边更近」判定，
拖拽时实时重算。

`PortLayoutTest.theLayoutNeverMeasuresText` 这条约束没有放松：`PortLayout` 的字节码里仍然不许
出现 `Font` / `FontMetrics`。3.2 的理由（尺寸必须在没有图形环境的地方也算得出来）没有因为改自由
布局而失效。

#### 文件格式：`slot` 变成只读的旧格式

`<pcomp>` 上多了 `width` / `height` / `caption-x` / `caption-y`，`<port>` 上多了 `x` / `y`：

```
<pcomp id="..." version="1" main="halfadder_v1" name="halfadder" locked="true"
       width="160" height="70" caption-x="75" caption-y="30">
  <port name="Sum"  side="top"    x="100" y="0"/>
  <port name="Ain"  side="left"   x="0"   y="30"/>
  <port name="Cout" side="right"  x="160" y="40"/>
  <port name="B"    side="bottom" x="70"  y="70"/>
</pcomp>
```

`slot` 属性**保留读，不再写**。只有 `slot` 的老文件走 `PortLayout.automatic` 重新铺一遍——注意
这是按**修好之后**的算式铺的，所以老文件装回来能用、能连线，但**不保证和当初发布时像素一致**。
在只有本人机器上那几个测试文件的阶段，这比留一份旧算式去复刻当年的 bug 划算。

端口签名 `PortSignature` 跟着从 `slot` 换成 `x` / `y`，`inReadingOrder` 按 y 再按 x 排。
**框的大小和标题位置故意不进签名**：把已发布的元件拖大一点、把名字挪一挪，不该逼出一个新版本，
因为端口一个都没动——所有坐标都是相对左上角那个锚点量的，框往右下拉，端口原地不动。

#### 窗口：草稿直接就是要画的东西

`PortLayoutDraft` 里每个 `Entry` 现在带 `side` / `x` / `y`，`moveTo` 吸网格、夹回框内、用
`PortSide.nearest` 重判边，`resize` 让**在动的那条边上的端口跟着边走**（另外两条边上的不动），
标题按比例跟着缩放。`previewLayout()` 和那套占位名的机器整个删掉了——画布现在直接读草稿。这不是
省事：`PortLayout` 现在拒绝重叠的端口，而拖拽过程中重叠是必然会经过的中间态，如果画布还是走
`PortLayout` 就画不出来。`Problem` 因此多了一条 `OVERLAP`，拦在保存按钮上而不是拦在渲染上。

只有**右边和下边**能拉。左上角是外观的锚点，每个端口坐标都是从它量的，拉左上角等于把所有东西
连同锚点一起搬走，那不是缩放。

按钮排里多了一个「自动排列」（`pcompArrangeButton`），把当前这堆端口重新交给 `automatic` 铺一遍。
自由布局需要一条回头路。

#### 三条测试断言跟着改了

改完之后有 28 条测试红了，全部是断言写错，不是代码错：

- `eachSidesPortsAreCentredOnIt` 量的是**离框边**的距离，而代码是在**两条带之间**居中的。改成
  从带量。
- `PortSignatureTest.movingAPortIsAChange` 和 `PcompVersionTest.changedLayoutsAreChangedSignatures`
  都用「把改过的端口列表再喂一次 `automatic`」来造「改动后」的布局，而重新铺一遍会把**别的端口
  也挪走**，于是「只有一个端口动了」永远不成立。改成 `PcompLayouts.moving(layout, name, ...)`
  ——只动一个端口，别的原样。这条比原来的写法更贴近现在的语义：自由布局里「挪一个端口」本来就
  应该只挪那一个。

顺手加了一条 `resizingTheBoxIsNotAChange`，把上面「框的大小不进签名」那个决定钉住。

### 12.10 元件名支持空格（2026-08-26）

维护者要求元件名能带空格。`5.4` 那三条校验里没有一条禁止空格，挡住它的是别的东西：元件名当时**同时**
是电路名（`circuitNameFor` 直接拿 `name.trim()` 拼 `_v<N>`），而电路名要过
`SyntaxChecker.isVariableNameAcceptable`，那条正则 `^([a-zA-Z]+\w*)` 里没有空格。

所以这次做的事是**把两个名字分开**：

- **用户名**（`PcompMetadata.name`）原样保留，空格照留。它是框里的 caption、`displayName()`
  「Half Adder v1」、管理面板的第一列、以及「这将创建 X v1」那句话。
- **电路名**（`mainCircuit`）由 `circuitNameFor` 派生：`\s+` 一律折成**一个**下划线，再拼
  `_v<N>`。折成一个而不是一个空格对一个下划线，是因为 `__` 也在 `SyntaxChecker` 的禁止之列。

派生只处理空格，**不救别的**。`Half-Adder` 里的连字符、`4 Bit Adder` 的首字符数字、
`Half _ Adder` 折出来的 `__`，仍然在保存按钮上被拦住。`pcompProblemBadName` 因此从
「这个名称不能用作电路名」改成把规则说出来：字母、数字、空格、下划线，且必须以字母开头——
用户现在会先试空格成功、再试连字符失败，得让他看得懂这两件事的区别。

一个不做不行的收尾：**元件栏里那一条的文字**。它来自 `AddTool.getDisplayName()`，转手就是
`SubcircuitFactory` 的 `getDisplayGetter()`，也就是电路名——于是元件栏会写 `Half_Adder_v1`，
用户会觉得空格根本没支持。新的 `PcompTool extends AddTool` 只覆盖 `getDisplayName()`，
其余一个不碰：

- `getName()` 故意不覆盖。它是 `PcompCatalogLibrary.toolsOf` 去重的 key，也是
  `<comp lib name>` 解析的依据，必须是电路名。
- `cloneTool()` 故意不覆盖。父类的实现走私有拷贝构造，把 `attrs` 完整克隆过去；覆盖它就得从
  factory 重新造一个，用户在这个工具上配过的属性会丢。代价是拖到工具栏上的那个副本会退回显示
  电路名——那是一个图标的 tooltip，比丢属性划算。

`~/.logisim-peler/components/` 里的文件名跟着电路名走，所以是 `Half_Adder_v1.pcomp`，没有空格。
两个不同的名字折出同一个电路名（`My And` 和 `My_And`）会撞车，这由 `destination()` 里那条既有的
`pcompNameTaken` 检查挡下，不是新问题。
